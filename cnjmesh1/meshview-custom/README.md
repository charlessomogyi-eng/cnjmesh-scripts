Units: `meshview-db.service` (writer, `startdb.py`) and `meshview-web.service` (`main.py`), both from `/home/somog/meshview` with `env/bin/python`. Database: `sqlite+aiosqlite:///packets.db` (about 14 MB plus a WAL file on Nov 12 2026).

## Local patch: NUL-padded gateway IDs (`mqtt-store-null-gateway-id.diff`)
Before Nov 12 2026 the Pi carried an undocumented edit to `meshview/mqtt_store.py` (3 lines): `int(env.gateway_id[1:].rstrip("\x00"), 16)` at the three places the old code parsed a gateway ID, so a gateway that sends its ID padded with trailing NUL bytes is still recorded. [V: `git diff` pasted Nov 12 2026; which gateway needs it is not recorded.]
Upstream 4.0.0 parses gateway IDs in one place, `parse_node_id()`, with the regex `^!([0-9a-fA-F]{1,16})$`, which would reject a NUL-padded ID and skip that gateway's PacketSeen rows with a "malformed gateway_id" warning. The patch adds one line to `parse_node_id()` (`value = value.rstrip("\x00")`). [V offline against upstream `0453de0`: applies cleanly, compiles, `!699a9390` with 0 to 3 trailing NULs gives the same ID, garbage still gives `None`.]

## Upgrade from v3.0.5.1+2 (`e4384f0`, Apr 2026) to 4.0.0 (Nov 9 2026) — DONE Nov 12 2026 6:53 PM
Upstream's `requirements.txt` is identical between the two, so no new packages. New optional `config.ini` sections (`[map_channel_colors]`, `[snapshot]`, `api = True`) have defaults. The old `starting = /chat` key is no longer read. The writer applies the migrations itself on start (drop `node.public_key`, daily-snapshot table, altitude column, packet index); the web unit waits for it.
Rollback = stop both units, `git checkout e4384f0`, restore the pre-upgrade `packets.db` copy (the migrations change the schema, so the old code needs the old file), start both units.

**Result [V, Charlie's pasted journal and curl, Nov 12 2026]:** all five migrations ran in about a second, the writer reconnected to the broker (`msh/US/#`), daily cleanup keeps 14 days (02:00) and the first daily snapshot is scheduled 01:00, the web unit answered HTTP 200 on port 8080. Backups from before the upgrade are in `~/meshview-backups` on cnjmesh1 (database copy, `config.ini`, the old `mqtt_store.py` diff). Unverified: the NUL-padding patch has not been seen doing anything (it only matters when a padded gateway ID arrives); a `malformed gateway_id` warning in `journalctl -u meshview-db` would mean a gateway is still being skipped.
Future updates: `git pull --ff-only` fails or conflicts only if `mqtt_store.py` carries the patch; use `git checkout -- meshview/mqtt_store.py`, pull, then re-apply the diff (check whether upstream fixed it first).

## Local patch: Fahrenheit on the node page (`node-fahrenheit.diff`, written Nov 13 2026, **not yet applied on the Pi**)
Requested in the Meshtastic Discord #general on Nov 13 2026 ("environment metrics to degrees fahrenheit"). Meshview 4.0.0 has no unit setting: the node page's Environment Metrics chart (`meshview/templates/node.html`) plots the node's Celsius reading and labels it "Temperature (°C)" [V: upstream `0453de0` source; no other place renders temperature]. The patch converts to °F (rounded to 0.1), relabels the legend, axis and CSV header, and also fixes the regex so below-zero readings are no longer dropped (it was `[\d.]+`, now `-?[\d.]+`; a reading of -5.5 °C previously showed as a gap). [V offline: applies cleanly on `0453de0`; the conversion tested for 21.5 C = 70.7 F, 0 = 32, -5.5 = 22.1, 100 = 212; a humidity line gives no temperature.] Not yet seen on the live page.
Apply on the Pi: `cd ~/meshview && git apply --check ~/cnjmesh-scripts/cnjmesh1/meshview-custom/node-fahrenheit.diff && git apply ~/cnjmesh-scripts/cnjmesh1/meshview-custom/node-fahrenheit.diff && sudo systemctl restart meshview-web`.
Like the gateway-ID patch, it must be re-applied after any upstream pull that touches `node.html` (`git checkout -- meshview/templates/node.html`, pull, apply again).
