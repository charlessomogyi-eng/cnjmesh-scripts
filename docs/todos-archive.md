### [RESOLVED Oct 23 2026] KPC1 went unresponsive — hard power-cycle fixed it, no reflash needed
Found during an unrelated check: `meshcore-cli -s /dev/kpc1 infos` returned "No response", and `-r` (repeater) also got no response, while `lsusb -t` showed the CP210x chip still enumerated — so the USB/serial bridge was fine but the ESP32/firmware side was hung. `screen /dev/kpc1 115200` showed total silence (no boot banner, no crash trace), confirming a true hang rather than a boot loop. Bot's own log showed it independently caught this: `WARNING - Radio health probe timed out` at 22:19:31, then a clean self-shutdown. A USB unplug/replug alone did NOT reset it (board stayed powered via its battery — UASB and battery are both power sources and need to be removed together for a real reset on these boards). Disconnecting **both** the USB cable and the battery lead for ~10s, then reconnecting both, cleared it: screen came back with a normal firmware boot, and `meshcore-cli infos` confirmed "CNJWeatherBot", same radio settings (910.525/500/SF10/CR5), same pubkey prefix `df8a4432`. `meshcore-bot.service` restarted cleanly and is active. **Lesson for next time a MeshCore companion board on this network seems dead with a blank screen/no response: try a full power cycle (unplug BOTH USB and battery, not just one) before assuming hardware failure or reflashing.**
