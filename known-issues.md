# known-issues.md — ALWAYS FETCH THIS

Short list of **active, currently-true gotchas** across the whole project (mesh infra and APRS/radio side). Written bluntly, in checkable terms, specifically so a fresh session catches these before declaring something "configured correctly." Delete an entry once it's actually resolved — this file is for what's *currently* true, not a history (that's `session-log.md`'s job).

**Rule for reviewing any screenshot or config claim:** a filled-in field is not the same as an active/working feature. Always check the actual status indicator, connection banner, or "connected/disconnected" label shown on screen — not just whether the input fields look populated/correct. Cross-check against this file before confirming anything is "fine."

## APRS / TD-H9 / K2GIA stations

- **K2GIA-7 (TD-H9, via KISSLink app): APRS-IS Companion connection had not been tested/verified as of Aug 23 morning.** Confirmed later same day that it DOES connect successfully when attempted (server `rotate.aprs2.net`, port `14580`, callsign `K2GIA-7`, passcode `16025`) — this was never actually a bug, just an unverified state that got misread once as "broken." Lesson: don't assume a disconnected status is a persistent problem without a repeat test — check current state fresh each time. Detail: `docs/aprs-bulletins-and-bridging-reference.md`, `docs/td-h9-app-field-reference.md`.
- **APRSdroid (K2GIA-5) does not actually send a message until "Start Tracking" is active**, even with a fully correct, apparently-connected APRS-IS setup. Messages sit queued locally (visible in your own sent list — easy to mistake for "sent") until Tracking is toggled on; only then does the app connect and flush the queue. No prominent warning in the UI beyond an easy-to-miss toast. This caused a long troubleshooting session on 2026-08-23 chasing a phantom delivery bug that didn't exist. **Always confirm Tracking is on before assuming a composed message actually went anywhere.** Full detail: `docs/k2gia-5-aprsdroid-reference.md`.
- **K2GIA-5 (APRSdroid) is Internet/APRS-IS only, by design — it has no RF path at all.** Don't assume a message from K2GIA-5 reached anyone over RF; it can only ever reach APRS-IS-connected stations. Detail: `docs/k2gia-5-aprsdroid-reference.md`.
- **APRS "CQ" is not a broadcast address.** It has no special meaning in APRS — the correct broadcast convention is `BLN1`-`BLN9` (bulletins). Confirmed via Graywolf source review + live RF test. Detail: `docs/aprs-bulletins-and-bridging-reference.md`.
- **K2GIA-10 (LoRa iGate) has a documented self-gating limitation** — its KISS TNC is TX-injection only, it cannot reliably hear/gate its own outgoing transmissions. A second RX-only board was ordered to address this (status: check `todos.md` / `docs/lora-aprs-reference.md` for current state).
- **Graywolf (K2GIA-1) has a known intermittent cpal/ALSA POLLERR audio bug** (RustAudio/cpal#730) — confirmed non-blocking (TX/beacon/iGate all unaffected), only degrades Graywolf's own RF self-hearing. Do not treat this as a functional outage if seen in logs. Detail: `docs/aprs-2m-graywolf-reference.md`.
- **Only one app (KISSLink OR TD-H9 APRS Messenger) can hold the BLE connection to the TD-H9 at a time.** If a connection attempt fails and the other app was recently used, check whether it's still holding the BLE link first.
- **K2GIA-9 (LoRa APRS Tracker, T3 V1.6.1) has no physical user button populated.** The button is required to reopen the WiFi config AP (`LoRaTracker-AP`) after first flash — without it, changing ANY setting later (callsign, SmartBeaconing, frequency) requires a full re-flash from scratch. **The IO15-to-GND pad-touch workaround (documented in `docs/lora-aprs-reference.md`) triggered unexpected "deep sleep" instead of reopening the config AP on Aug 26, 2026 — do NOT trust this method as confirmed-safe.** Board recovered fine via USB unplug/replug, no lasting harm, but root cause unconfirmed. Use full re-flash instead if config access is needed (slower, but confirmed-safe fallback).
- **K2GIA-9 Bluetooth Classic pairing via Android Settings does not work** (confirmed on Pixel 7) — device shows as scannable/selectable but tapping it produces no pairing prompt, no error, nothing in the board's serial log. Matches an open, unresolved upstream firmware issue (richonguzman/LoRa_APRS_Tracker #275) and a documented pattern of ESP32 Bluetooth Classic SPP devices failing to pair on modern Android specifically. **Workaround: skip OS Settings entirely — select the device directly from inside APRSdroid's own "TNC Bluetooth Device" picker.** This does eventually connect, but can take several minutes completely silently (no toast, no visible status change) before the board's log shows `[INFO][Bluetooth] Client connected!`. Don't assume failure just because nothing visibly happens right away. Full detail: `docs/lora-aprs-reference.md`.
- **K2GIA-9's Bluetooth Classic connection does NOT auto-reconnect once dropped.** Confirmed via overnight serial log: disconnected once, stayed disconnected 10+ hours straight with zero automatic retry from either side. This is the real explanation if a message won't send/go green even though "it worked fine yesterday" — check Bluetooth connection status first, don't assume it's a range/antenna problem (this was initially mistaken for exactly that). Walking closer to the tracker and reopening the app appears to force a fresh reconnect attempt.
- **APRSdroid has no multi-profile support.** Switching it to point at K2GIA-9 (Bluetooth/TNC-KISS) overwrites the same config previously used for K2GIA-5 (Internet/APRS-IS). Switching back is a manual, full reconfiguration each time — there's no saved second profile to flip between.

- **Update 2026-10-13 (from Jul 24-25 range-test handoff; [V]/[I] tags per that file):** aprs.fi only shows packets that reached APRS-IS. "Not on aprs.fi" means "not gated", NOT "not transmitted" — to prove RF reach you need another station's iGate or an RX-only second board. Jul 24 tests (K2GIA whip CQ, K2GIA-10 roof-antenna CQ) were therefore inconclusive, not negative. Detail: `docs/lora-aprs-reference.md`.
- **Update 2026-10-13 ([S] — from screenshots described in chat):** `aprs-tnc-web` shows only a "CQ Sent Successfully!" popup for a CQ send; the CQ does not appear in its Conversations list afterward, so the app cannot confirm transmission or delivery. Use aprs.fi or the LoRa syslog instead.
- **Update 2026-10-13 ([V] from Graywolf source read Jul 24; exact buffer size [I]):** Graywolf's packet API holds roughly 1000 packets / ~30 min, so it cannot answer "did my message go out?" half an hour later. Use aprs.fi or `journalctl -u graywolf`. Auth method: `docs/aprs-2m-graywolf-reference.md`.
- **Update 2026-10-13 ([S] — from APRS-IS filter documentation looked up in chat; not re-run against a live server):** APRS-IS filter terms separated by spaces are **OR'd**, not AND'd. A filter like `r/<lat>/<lon>/150 t/moi` returns everything within 150 km **plus** all messages/objects/items anywhere on the network. To combine type and distance use the single-term form `t/<types>/<call>/<km>`, e.g. `t/moi/K2GIA-1/150` (radius anchored on that station's last reported position; `/K2GIA-5/` would follow the phone). Filters only apply at the next login (Stop then Start Tracking in APRSdroid). The "settled" filter in `docs/k2gia-5-aprsdroid-reference.md` predates this finding and is unverified — see the update note there.

## Logging, backups and alert-text gotchas (found Oct 22-23 2026)

- **Raspberry Pi OS keeps the journal in RAM by default** (`/usr/lib/systemd/journald.conf.d/40-rpi-volatile-storage.conf` sets `Storage=volatile`): logs are capped (~37 MB on cnjmesh1, about 3 hours of history) and **vanish at every reboot**. Fix applied with a higher-priority drop-in `/etc/systemd/journald.conf.d/50-persistent.conf` (`Storage=persistent`, then `mkdir /var/log/journal`, `systemd-tmpfiles --create --prefix /var/log/journal`, restart journald, `journalctl --flush`): cnjmesh2 Oct 16 (took effect only at the Oct 22 reboot), cnjmesh1 Oct 23 19:22, cnjmesh3 Oct 23 21:10. **Any new Pi needs the same.** Verify: `systemd-analyze cat-config systemd/journald.conf | grep ^Storage` (last line wins) and `ls /var/log/journal/*/`.
