On the mesh in about 10 minutes

Get on the mesh

You need one inexpensive LoRa radio and the free app for your phone or computer. No license, no subscription. Start with the quick start for whichever protocol you're running; the advanced reference below is there when you want to be a good mesh citizen and tune your node properly.

What you need

At minimum, one handheld node — a small LoRa radio that's your personal connection to the mesh. Popular starting boards come from Heltec, RAK, and LilyGo, and generally run from around $30. Many people later add a second "roof" node up high to make a reliable first hop into the wider network.

If you want to run both protocols at once, you'll need a separate device for each — a single radio runs one firmware at a time. That's a common setup here, and it's the best way to reach everyone.

Not sure what to buy? Hop into one of our Discords and ask before you spend anything. People will point you at a board that's known to work well on our network and save you a false start.

Meshtastic quick start

Meshtastic is open-source mesh messaging over LoRa — encrypted group channels and direct messages, with your phone connected to the node over Bluetooth. Our regional channel is CentralNJ, and it's the home of the Central and South New Jersey Meshtastic community.

  1. Flash your device with the latest firmware at flasher.meshtastic.org.
  2. Install the Meshtastic app and pair with your node over Bluetooth.
  3. Add a new channel named CentralNJ using the settings below.
  4. Optional, to appear on the maps: point MQTT at the server below and enable Uplink + Downlink on the CentralNJ channel, with "OK to MQTT" turned on in your LoRa settings.
channel : CentralNJ
psk : f+WQoPgd06tk0n3Kl2bUmNVGO7TcPkxchPD6QqMkYRg=
mqtt : mqtt.meshtastic.org
login : meshdev / large4cats
On the map MQTT is entirely optional — the mesh works over RF whether or not you connect it. It only controls whether your node shows up on Meshview and Malla. "OK to MQTT" has to be enabled on your node for that to happen.

MeshCore quick start

MeshCore uses smart routing rather than flooding: every user runs a companion node, and repeaters and room servers carry traffic across the area. Messages are encrypted end to end, and apps are available for Android, iOS, and desktop.

  1. Flash your device with the latest firmware at flasher.meshcore.io.
  2. Install the MeshCore app on your phone or desktop and pair it with your device as a companion.
  3. Set your radio to the US region defaults so you're on the same air as the rest of us (see the table below).
  4. Add the local channels and send a hello — then check CoreScope to see yourself appear.

These are the standard US MeshCore parameters, shared with our neighboring networks so traffic can cross between meshes. If your messages aren't getting through, nudging the coding rate up can help — it stays cross-compatible.

Advanced: be a good mesh citizen

A wide-area mesh has different needs than the small personal mesh Meshtastic ships for by default. A few settings, applied by everyone, keep the whole network fast and usable. None of this is required to send your first message — but tuning your node this way is the single biggest favor you can do the rest of us. The short version: send less background traffic, and let the right nodes do the relaying.

Meshtastic node roles

Pick the profile that matches how the node is used. The goal is that mobile and personal nodes don't accidentally stomp on better-placed infrastructure when relaying.

Handheld / mobile node

A node you carry — pocket, bag, car.

SettingSuggested
RoleCLIENT_MUTE
PositionSmart position, 30 min+ interval, 100 m+ distance, altitude off
TelemetryOff
Device infoLong interval (e.g. 19 hr)
Hop limitSet to match network guidance

CLIENT_MUTE keeps a mobile node from relaying at the wrong moment — handhelds often hear the network at a worse signal than fixed nodes, so if they relay first they can crowd out a better-placed node. It also avoids the "false ack" trap when two of your own nodes sit close together.

Stationary personal node (desk / roof you send from)

SettingSuggested
RoleCLIENT
PositionFixed position, altitude on, smart position off
TelemetryOff
Device infoLong interval (e.g. 19 hr)

A fixed node you also message from is a good conditional relay. A set fixed position is better than GPS here, since a stationary node can otherwise wander on the map from GPS drift. Altitude is worth keeping — it helps everyone understand real coverage.

Infrastructure node (relay only, you don't message from it)

SettingSuggested
RoleROUTER / CLIENT_BASE (per network guidance)
RebroadcastCore portnums only
PositionFixed, altitude on
Telemetry6 hr+ interval
Remote adminStrongly recommended

"Core portnums only" keeps noisy or custom app traffic off the backbone so airtime stays available for text. Position really matters on infrastructure — it's how users understand which nodes are covering them.

One rule above all Please don't run high-traffic apps like TAK or Reticulum over the shared mesh — they saturate the limited airtime and make it unusable for everyone. If you want to experiment with those, do it on your own private channel.

MeshCore repeaters

Running a repeater is one of the most useful things you can do for MeshCore coverage. The key idea is the same as above: keep advert traffic low so the mesh stays efficient. For the full repeater configuration — advert intervals, hop limits, and region setup — reach out in the Discord and we'll get you set up with settings tailored to CNJ.
